# 魔盒幸存者 → 独立游戏（对标弹壳特工队）调研

> 目标：把 `src/games/survivor/game.js`（Web 原型）做成弹壳特工队（Survivor.io，Habby）量级的独立小游戏。结论先行：**玩法已验证，差距在「内容工业化 + 商业化 + 平台发行」，引擎换 Cocos，砍掉原 Canvas 当玩法实验场。**

## 1. 对标：弹壳特工队是什么量级
- 引擎 Cocos Creator，竖屏单手、自动攻击、武器进化、章节闯关。
- 营收靠 **内购 + 激励广告 + 战令/月卡**，留存靠 武器/装备养成、章节、活动。
- 体量：数十武器+进化、上百怪、几十 Boss、长线赛季；几十人团队、长期运营。
- 我们的差异化：**东方百鬼夜行题材 + 镇夜进度玩法**（已在原型成形），这是能打的差异点，别丢。

## 2. 现状 vs 独立产品差距
| 维度 | 现原型 | 独立要求 | 差距 |
|---|---|---|---|
| 手感/构筑 | ✅ 已验证 | 同 | 小 |
| 渲染 | Canvas，66 怪≈44fps | 300+怪稳60 | 引擎/池化/网格 |
| 内容量 | 试玩级 | 30+武器/100怪/30关 | 大 |
| 美术 | SVG帧 | 专业骨骼+特效 | 大 |
| 商业化 | 无 | IAP+广告+战令 | 全新 |
| 发行 | GitHub Pages | 微信/抖音/出海 | 全新 |
| 数值/运营 | 手调 | 配置+埋点+AB | 中 |

## 3. 引擎：Cocos Creator 3.8 + TS（沿用 [[05-cocos-technical-solution]]）
原型不迁移，作玩法/数值实验场；正式 runtime 重写：EntityManager + ObjectPool + 网格碰撞 + Skill/Spawn/Boss/Drop/Objective 系统。300 怪靠：对象池、空间网格、合批、图集、低端机降特效。

## 4. 内容工业化（最大成本）
- 武器/匣术 30+、进化 12+、怪 100+、Boss 12+、章节 6+、关卡 30+，全配置驱动（表）。
- 美术：竖屏地图、Spine 角色/怪、技能特效、UI 一套、图标百级 → 外包+量产管线。
- 数值：成长曲线、掉率、付费点用 Excel/JSON 配，可热更。

## 5. 商业化
- 内购：角色、皮肤、礼包、月卡。广告：复活、双倍、刷新。战令：赛季线。
- 接入激励广告 SDK、支付、客服、防沉迷合规。

## 6. 发行：Web 内测 → 微信小游戏 → 抖音 → 出海
小游戏约束：首包/分包/启动/低端机/缓存/审核（见 [[07-mini-game-platform-and-roadmap]]）。

## 7. 团队/周期/预算（粗估）
- 最小：策划1+客户端2+美术2+运营0.5，6-9 月到可测 MVP，12-18 月到正式。
- 预算：人力为主 + 美术外包 + 买量；出海需本地化。
- 个人/小团队替代：先 MVP（3角色/12技能/3章）验证留存付费，再决定加码。

## 8. 迁移步骤
1. 抽数值/掉率/波次成 JSON，沉淀到原型。2. Cocos 原型跑核心手感(1角3技4怪1boss)。3. runtime 框架(池+网格)300怪。4. MVP 内容。5. 商业化+埋点。6. 微信测试→留存付费看数→加码/出海。

## 9. 风险
赛道红海、买量贵、内容产能、低端机性能、合规。题材差异化 + 小步验证留存(次留>40/40%)再投放。
