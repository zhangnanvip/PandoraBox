# 反思与后续 Backlog

## 1. 当前 PandoraBox 原型的价值

当前 `src/games/survivor/game.js` 已经验证了很多方向：

- 竖屏拖动画布移动。
- 自动攻击。
- 技能升级。
- Boss 节点。
- 遗物和宝箱。
- 关卡事件。
- 角色能力。
- 地图目标。
- 局外天赋。
- 续玩存档。

这些非常适合作为玩法实验场。后续新增机制可以先在 PandoraBox 里快速验证，再沉淀到 Cocos 独立项目。

## 2. 当前原型的不足

### 2.1 美术气质不足

问题：

- 角色、怪物、技能多为 Canvas 几何绘制。
- 不能支撑《百鬼夜行》的题材记忆。
- 怪物之间的辨识度仍然不够强。

方向：

- 独立项目必须使用 sprite、序列帧、粒子和 UI 资产。
- 先做一套可复用的百鬼图形语言。

### 2.2 内容结构还偏试玩

问题：

- 当前已经开始从“单个割草模块”往百鬼夜行试玩版迁移，但仍缺少完整章节地图、剧情推进、Boss 叙事和长期目标。
- 敌人已经有初步百鬼谱系，但仍需要更强的行为差异、图鉴解释和动画资产。
- 当前百鬼录还只是轻量战斗内提示，独立项目需要做成完整图鉴页，包含来历、弱点、掉落和推荐匣术。
- 伤害统计已经有原型，但还没有接埋点，也没有做按章节、按玩家等级的留存分析。

方向：

- 用章节+关卡+碎片+图鉴组织内容。
- 通关不靠时间，而靠击杀积分、目标、精英和鬼王击破形成镇夜进度。

### 2.3 数值工具不足

问题：

- 数值直接写在代码里，长期调优成本高。
- 关卡难度、敌人曲线、技能成长缺少可视化。

方向：

- 独立项目必须配置化。
- 最少要有 CSV/JSON 导入和 schema 校验。

### 2.4 性能边界需要更早设计

问题：

- Canvas 原型可快速迭代，但难以支撑大量动画资产和平台适配。

方向：

- Cocos 项目从第一天就做对象池、空间分桶、特效降级。

## 3. 竞品启发

割草生存类长期耐玩的关键不是单纯怪多，而是：

- 玩家每局都能形成不同构筑。
- 技能进化有明确目标。
- 怪物行为逐步复杂。
- Boss 有机制和反制窗口。
- 局外成长提供长期目标。
- 每局结算都让玩家知道下一步要追什么。

需要避免：

- 所有关卡只有怪物血量变高。
- 所有技能只是不同颜色的子弹。
- Boss 只是大血条。
- 玩家不看屏幕也能赢。
- 广告破坏战斗节奏。

## 5. PandoraBox 内可继续验证的事项

如果还要在当前大厅里继续优化割草生存，可以做：

- 继续把现有敌人按百鬼谱系重命名并调整绘制轮廓。
- 继续根据镇夜进度来源占比调关卡，避免普通击杀、地图目标或事件奖励其中任何一项独大。
- 继续按章节调试敌人/事件/危险区占比，让每章形成可识别的战斗节奏。
- 在 StagePhase 之上继续补具体刷怪阵型，例如前方合围、背刺伏击、裂隙环形增援和 Boss 护卫线。
- 继续增加 Boss 机制的弱点窗口和阶段差异，危险范围预告已先接入第一版。
- 继续优化升级符牌，加入进化预览、流派标签和重掷资源。
- 将升级选择扩展为“流派构筑推荐 + 当前威胁推荐 + 可重铸资源”，避免玩家只看稀有度选牌。
- 继续优化怪物轮廓和颜色区分，下一步重点是低阶怪的动画帧和死亡差异。
- 扩展死亡原因结算，加入“主要伤害来源”和“推荐应对”。
- 将百鬼应对提示扩展为配置表字段，并沉淀到 Cocos 项目的 `EnemyConfig`。
- 将伤害来源统计接入埋点，并在调试面板里查看每关主要死因。
